Operational Dashboards: Study Management & CRA Homepage

Last updated 2026-08-15

Two Workbenches

CTMS provides two workbenches sharing the Study / Country / Site three-level scope selector:

WorkbenchEntry pointAudience
Study Management HomepageStudy Management → Study Management HomepageStudy managers (operational overview)
CRA HomepageSite Monitoring → CRA HomepageCRAs (monitoring workbench)

After selecting a Study, the widget grid loads; selecting Country / Site further scopes the metrics, and clearing them returns to study level.

Study Management Homepage

WidgetContent
Summary MetricsSite Status / Enrolled / Complete progress (can be 0 with no data)
Monitoring ComplianceVisits Overdue semantics and Visit Report Cycle Time (can be None Due)
Monitoring StatusCounts distributed by visit type
MilestonesMilestones generated by Plan Study / Ready to Enroll
My TasksPersonal tasks
Enrollment StatusEnrollment status (empty state allowed)

CRA Homepage

WidgetContent
DetailsStudy details
Summary MetricsSummary metrics
Monitoring PlanScope-filtered visit plan; click a visit name to drill into the Monitoring Event detail
My TasksPersonal tasks
Enrollment StatusEnrollment status
QualityQuality issue / deviation counts (may reflect open deviations; empty state allowed)

Division of Labor with the TMF Homepage

The TMF Homepage measures document-side health (completeness, timeliness, document quality); the two CTMS homepages measure process-side operations (site status, visit compliance, enrollment progress). The three entry points coexist in one Vault, used by different roles.

Note

If Homepage Monitoring Status is empty: verify the correct Study is selected and the Monitoring Event's Study/Country/Site bindings are correct, then refresh.

Required Permissions & Roles

TypePermissionControls
TabStudy Management Homepage / CRA Homepage: ViewAccessing the dashboards
ObjectStudy / Study Site / Monitoring Event / Milestone / Subject / Issue: ReadData for each widget
ObjectClinical User Task: ReadMy Tasks widget

Widget data is scoped by dynamic sharing: users only see data within the scope (study/country/site) granted by their Team Role.
